- 의도하지 않은 겹침·잘림·미해결 자리표시자가 없다.
- 제목 줄바꿈은 기존 수동 `<br>`에 종속되지 않고 레이아웃 폭에 맞게 균형 조정되며, 고정 높이 컨테이너 안의 본문도 clipping ancestor 검사에서 통과한다.
- 사례 수치와 이력은 로컬 노트 또는 GitHub 저장소에 근거한다.
- 발표자 노트에 시간, 말할 핵심, 근거 출처가 포함된다.
- 실제 화면은 이미지 배경만으로 슬라이드 전체를 위장하지 않고, 제목·설명·도식은 실제 HTML 요소로 구성한다.
- 발표 화면과 발표자 노트에서 `~입니다/~합니다` 종결을 사용하지 않는다.
- Deck Factory 오버레이가 채운 회색 카드와 장식성 그림자를 제거하고, 콘텐츠 슬라이드에 paper-light 토큰과 4모서리 크롬을 적용한다.
- 제공 자료에서 선별한 실제 화면은 파일명·날짜·출처 묶음을 발표자 노트에 남기고, 개인정보·연락처·계정 정보가 보이는 이미지는 사용하지 않는다.
- 표지·목차·각 사례의 첫 장뿐 아니라 후속 설명 장에서도 사용자가 말한 사건 순서와 핵심 표현이 생략 없이 이어져야 한다.
- 일반현황·SNS·환경정책과·신규회원·발표제작 공정에는 실제 UI·문서·코드·시연 프레임을 충분히 배치하고, 전체 덱에서 검증된 이미지 배치 45개 이상을 확보한다.
- HTML에 `<video>`를 남기지 않고, 일반현황·SNS·녹색제품 세 시연을 각각 3개 이상의 시간 순 캡처로 구성한다.
- 실제 증거 화면에 로그인 팝업·접속 차단·무관한 홈 화면·현재 발표와 다른 이전 덱이 들어가지 않는다.
- 제공된 18장 Design Interior PPTX를 전부 검사한 뒤, 슬라이드 캡처를 배경으로 붙이지 않고 토큰·타이포·헤더·숫자·이미지 매트·러스트 프레임을 CSS/HTML로 재구성한다.
- 각 슬라이드의 Design Interior 레이아웃은 현재 배열 순번이 아니라 HTML의 명시적 `data-di-layout`·`data-di-source`로 고정한다. 중간 장을 추가·삭제해도 뒤 장의 레이아웃이 밀리지 않아야 한다.
- 기존 HTML의 `cards/process/grid` 외형을 유지한 채 색만 바꾸는 방식은 불합격이다. 각 장이 원본 18장 중 어느 레이아웃 유형을 계승하는지 식별 가능해야 하며, 이미지 크기·제목 위치·여백·본문 밀도도 해당 유형에 맞춰 재편성한다.
- 과정 도식의 자동 화살표가 텍스트·번호·단계 블록을 침범하지 않으며, 필요 없는 자동 연결선은 제거한다.
- Genspark 장은 `DESIGN.md + 발표 내용 → 18장 PPTX 현실화 → 렌더·레이아웃 검증`을 명시하고, 시제품 장은 실제 화면을 세로로 짧게 압축하지 않고 넓고 길게 보여주면서 핵심 사업 수치를 함께 제시한다.
- 새로 만든 설명용 이미지는 실제 캡처처럼 오인되지 않도록 `개념 시각화` 또는 `발표용 재구성`으로 표시하며, 텍스트 장식이 아니라 해당 장의 판단 구조·수치·작동 원리를 직접 설명한다.

- 프론티어 모델 장은 `Fable 5`, `GPT-5.6`, `Kimi K3`의 정확한 명칭과 공식 화면을 사용하고, 가격·접근성·용도 판단을 함께 제시한다.
- Fable 5 중단·복구 타임라인은 공식 기록과 일치하며, 미확인 통신사 연계설을 사실처럼 표현하지 않는다.
- AI 챔피언 개인 성과와 정부 공식 과정 설명, 향후 해커톤 구상을 시각적으로 구분한다.
